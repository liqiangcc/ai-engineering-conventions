# Issue 进度与中文标签

## 目的

以 Issue 为研发任务入口，用中文标签定位当前阶段，用正文、评论和验证证据解释实际进展。阶段、任务类型和阻塞状态分别维护，减少重复进度表和状态歧义。

## 标签集合

GitHub 与 GitLab 使用相同的完整标签名，包括中文冒号 `：`。

| 分类 | 标签 | 含义 |
|---|---|---|
| 阶段 | `阶段：待澄清` | 明确需求、用例、规则、范围和 AC |
| 阶段 | `阶段：待开发` | 关键需求已明确，尚未开始实现 |
| 阶段 | `阶段：开发中` | 设计、编码、相关测试和代码审查 |
| 阶段 | `阶段：待验证` | 实现与代码审查完成，执行交付验收 |
| 阻塞 | `阻塞` | 有工作无法继续，需记录原因及解除条件 |
| 类型 | `类型：功能` | 新增或调整业务能力 |
| 类型 | `类型：缺陷` | 修复不符合预期的行为 |
| 类型 | `类型：技术任务` | 技术改造、配置或工程维护 |
| 类型 | `类型：工作计划` | 组织周期或目标下的多项任务，见[工作计划与查找](issue-planning.md) |

采用本流程的开放研发任务 MUST 恰有一个阶段标签和一个主要类型标签；`阻塞` 可与阶段并存。阶段标签只表示当前阶段，不承担完成证明；此约束用于避免同一任务同时显示多个进度。

不新增“已完成”标签：完成由 Issue 关闭状态及收尾结论表达。模块等现有标签可以保留。工作计划和长期知识 Issue 不强制套用研发任务阶段；承担研发验收的父任务仍遵守研发阶段约定。

## 阶段推进

| 变化 | 条件与动作 |
|---|---|
| 创建 → 待澄清 | 输入仍有影响范围、行为或验收的关键疑问 |
| 创建或待澄清 → 待开发 | 范围、主要 UC、规则与 AC 已明确，关键疑问已解决，最小验证方案可执行；纯技术任务使用适用契约与验收条件 |
| 待开发 → 开发中 | 开始设计或实现，核对必要依赖，按任务范围推进 |
| 开发中 → 待验证 | 必要实现、相关测试和代码审查完成，关联 MR / PR 与提交，进入交付验收 |
| 待验证 → 关闭 | 范围内 AC 有证据、必需验收通过，约定交付已完成；移除阶段及阻塞标签，保留类型标签 |

关闭条件与测试状态遵循[需求到 Issue 流程](requirement-to-issue.md)及其引用的验证规范。包含部署验收时，必须有实际运行版本的验证证据；不能仅凭合并代码关闭。

标签允许根据实际情况回退或直接进入已满足条件的阶段，不要求形式上逐个经过。验证发现实现问题时回到开发中；发现关键需求歧义时回到待澄清，并记录原因及影响。重新打开任务时恢复恰当的阶段标签。

取消、重复或不再实施的任务可以关闭，但必须记录原因，不能报告为验收完成。重复任务链接到继续承接工作的 Issue。

## 阻塞与更新频率

出现阻塞时添加 `阻塞`，保留当前阶段，并记录：阻塞原因、影响的工作、解除条件与下一步；部分阻塞时继续推进独立工作。解除后移除 `阻塞` 并更新结论。

仅在阶段变化、发生或解除阻塞、重要共识变化、取得关键验证结果时更新。正文保存当前结论，评论按需保留变化依据，不记录逐条操作日志，也不维护第二份人工进度表。

## 从 Issue 恢复工作

```text
读取正文、评论、标签和关联任务
→ 核对代码版本、MR / PR 与验证证据
→ 找到当前阶段尚未满足的条件
→ 推进任务
→ 更新结论、证据和标签
```

标签与实际证据冲突时先说明并修正，不能依据标签跳过未完成工作。父任务按完整用例组合及约定交付判断阶段，不从子任务数量推算完成。

## 平台执行与既有标签迁移

标签的查询、创建和增删遵循[Issue 命令行操作](issue-cli.md)，GitHub 使用 `gh`，GitLab 使用 `glab`。切换时移除旧阶段并添加新阶段，保留无关标签，随后读取核对；不依赖平台自动保证互斥。

项目采用时检查现有标签，等价英文标签按下表替换，避免维护两套进度。只迁移授权范围内的任务，不批量修改无关历史 Issue。

| 既有标签（如存在） | 中文标签 |
|---|---|
| `stage:clarifying` | `阶段：待澄清` |
| `stage:ready` | `阶段：待开发` |
| `stage:developing` | `阶段：开发中` |
| `stage:verifying` | `阶段：待验证` |
| `blocked` | `阻塞` |
| `feature` | `类型：功能` |
| `bug` | `类型：缺陷` |
| `technical` | `类型：技术任务` |

自定义旧标签先确认语义再映射；颜色不承载业务含义，不强制统一颜色。

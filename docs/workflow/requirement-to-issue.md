# 从需求输入到研发 Issue

## 目的与边界

将不同来源的需求整理为可设计、可实现、可验证的研发任务，降低澄清、交接和恢复上下文时的认知成本。

需求输入可以是一句话、对话、文档、截图、缺陷反馈或已有任务，不要求来自特定平台。研发 Issue 使用 GitHub 或 GitLab 承载，通过 `gh` 或 `glab` 命令行操作，具体执行规则见[Issue 命令行操作](issue-cli.md)。本地文档或对话可承载发布前草稿。

使用[研发 Issue 模板](../templates/development-issue.md)，按阶段补齐信息。创建草稿时不要求设计和验证已经完成。

任务阶段、阻塞及类型使用[Issue 进度与中文标签](issue-progress.md)；后续设计、开发和验证从同一 Issue 恢复并推进。

## 需求整理与拆分

```text
需求输入
→ 理解与澄清（可在草稿 Issue 中进行）
→ 明确用例、规则、范围和验收标准
→ 设计
→ 实现
→ 验证与交接
```

- 原始输入与解释 SHOULD 分开记录；已确认共识应注明确认人或确认来源及时间。假设和待确认问题 MUST NOT 表述为已确认需求，避免把解释误当成业务依据。
- 业务任务 SHOULD 按可独立验收的用例目标拆分，一个 Issue 以一个主要用例为中心。已有能力的修复或增强引用原 UC，不因新任务重新分配 UC。
- 前端、数据库、接口和测试通常是同一用例的实现工作，不按技术层机械拆成业务用例；确需并行交付时可建关联子任务，并保留完整用例的验收责任。
- 一个需求包含多个用例时，可用父任务关联各 Issue，并记录需求点到用例 / AC 的覆盖关系。该关系用于检查遗漏，不保证输入本身已经完整。
- Bug 补充复现、正确行为依据和回归证据；纯技术任务允许 UC / BR 不适用，注明原因，不虚构业务身份。
- 跨仓库用例记录参与仓库、契约、依赖与联调验收责任。是否拆子任务取决于交付边界，不默认每个微服务都需要修改。

## 用例、规则与验收标准

| 内容 | 职责 |
|---|---|
| UC | 参与者在什么条件下完成什么业务目标，以及流程和结果 |
| BR | 可以独立描述、修改和验证的业务决定 |
| AC | 用具体场景说明如何判断本次任务完成 |

Issue SHOULD 明确涉及的规则：已有规则引用权威定义；新增或变更规则写明拟议内容、依据和确认状态。没有独立 BR 时注明不适用；交互细节可以直接写入 AC，不要求每条 AC 都有 BR 或每条 BR 都有独立类。

AC MUST 来自需求共识、业务规则或公开契约，不得从当前实现反推，防止实现和测试相互自证。覆盖主要成功、关键拒绝与边界场景（适用时）。

## 按阶段补齐

| 阶段 | 所需信息与判断 |
|---|---|
| 创建草稿 | 原始输入、初步目标、已知疑问；其他内容允许待补充 |
| 进入实现前 | 范围和主要 UC 明确；规则与 AC 有依据、结果可判断；影响本次行为或契约的关键疑问已解决；确定最小验证方案 |
| 设计与实现 | 按复杂度记录职责、接口、数据和跨仓库影响；关联实际代码变更；新增疑问只阻塞依赖其结论的工作 |
| 验证与完成 | AC 对应验证证据；未完成和未验证项有明确记录；按约定交付范围判断是否完成 |

澄清或实现中发生范围变化时，更新当前结论与 AC，并保留变更依据，检查对设计、代码及测试的影响。不能通过删掉未满足的 AC 静默缩小范围。

实现和验证遵循[AI 开发流程](ai-development.md)与[验证工作流](../testing/verification-workflow.md)。Issue 不复制测试状态、汇总结果或发布门禁的定义。任务包含部署验收时，仅合并代码不足以完成任务；部署不在范围内时，明确交付边界和部署验证状态。

## 上下文与权威来源

Issue 是本次任务的上下文入口：保存当前共识、决策、阻塞点和下一步，链接代码变更与证据。恢复工作时核对实际分支、提交、工作区和验证产物，不能把旧进度描述当作实时事实。

- 当前长期规则保存在项目确定的权威位置；Issue 保留本次拟议变化及历史依据。规则生效时更新权威定义并链接，避免两份当前规则。
- AC 在 Issue 或已有 BC 中选择一个权威位置，另一处引用。局部编号可用 `AC-01`，跨任务引用必须带任务完整链接或标识；不把 Issue 编号替代 UC / BR 身份。
- BC / INC 的适用性遵循[稳定标识体系](../traceability/identity-system.md)。已有记录直接关联；使用 Issue 不意味着每个任务都要另写同内容的 BC / INC 文档。
- 环境信息、稳定验证命令和项目约束引用项目事实源；执行证据记录当时实际环境与版本，不在模板中固化具体项目配置。
- 可由 MR、提交、CI 或索引推导的明细优先链接，不增加人工同步清单。简短任务可直接内联设计或证据，无需为每个栏目创建文件。

通用模板先在真实功能与 Bug 任务中试用，再根据反复出现的信息缺口调整；自动化只执行已经稳定的要求。
